# MVP Minimum Shippable Cut Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the smallest Prep Desk a DM can rely on. A DM can:

1. create a campaign with session-zero lines and veils;
2. open the Forge, roll any of the 15 generators under the campaign's **current** safety, lock fields, reroll, and save the card to the Codex;
3. keep a Codex of entries (NPC, place, note and the rest) with wiki links, search and edit;
4. back up to a JSON file and restore it;
5. use it offline as a PWA, with nothing leaving the device.

**Architecture:** The data layer from S2 Tasks 1–8 is reused as delivered (`apps/web/src/data`, `content/safety.ts`). The UI adds:

- one shell, with a DB provider, hooks, campaign-scoped routes and a smaller TopBar;
- three kit pieces: `Dialog`, `EmptyState` and `Pagination`;
- one shared hook, `useDirtyBlocker`;
- nine page routes, each on a named page pattern.

There are no slide-overs, popovers or comboboxes. Create and edit entry are one Form (page) component (decision M-D4). The dev `/forge-preview` route stays for the kit. The real Forge at `/c/:cid/forge` replaces its role, built from its working generator picker.

**Tech stack:** unchanged. TypeScript (strict), React 18, react-router 7, Dexie 4 + dexie-react-hooks, zod 4 (the engine's instance), Vitest + Testing Library + fake-indexeddb, and Playwright + @axe-core/playwright. **No new dependencies; `pnpm-lock.yaml` stays untouched.**

## Global constraints (summary; the S2 plan's full list binds)

- **Engine boundary:** nothing in `packages/` changes. If an engine change looks necessary, stop and report it to the controller.
- **Safety beats everything:**
  - Every engine call goes through `content/safety.ts` (`rollGenerator`, `rerollCard`, `recheckCard`, `linedTopics`), always with the campaign's **current** `safety`. The ESLint engine-call ban stays.
  - Lines override locks (R22).
  - The UI never filters text itself.
  - The DM's own text is never filtered or flagged.
  - A new campaign stores `{ lines: ['child-harm'], veils: [] }`.
- **Accessibility:**
  - targets are at least 44×44 px, with the 2 px pencil focus ring;
  - text contrast is at least 4.5:1, and borders at least 3:1, in light and dark;
  - `prefers-reduced-motion` is respected;
  - there is no horizontal page scroll at 1194, 834, 1440, 390, 375 and 1280;
  - axe reports zero serious or critical findings in light and dark.
- **Styling:** tokens in `styles/tokens.css` only, with no raw hex in component CSS. Ink goes on borders, never on text. Keys are R31 raised keys. **No pills.** Each task owns its own CSS file (listed per task).
- **Privacy:**
  - no third-party requests;
  - `public/_headers` (the CSP) is **never** loosened;
  - no `dangerouslySetInnerHTML`, `innerHTML` or HTML strings: wiki text renders as React nodes.
- **Copy (§11):**
  - sentence case, warm, second person, no exclamation marks;
  - no "AI" and no "generate"; the verb for randomness is Roll;
  - verb-first buttons, never OK, Submit or Continue;
  - labels always visible;
  - errors say what happened and what to do next, in under two sentences;
  - destructive confirms name the thing.
  - Raw field keys (`knownFor`) are never shown; labels come from `content/fields.ts` (M2).
- **UX skills:** read `.ux-profile.md` and the matching skill before UI work. Every page task names its pattern in its header (done below), before markup.
- **TDD and no vacuous tests:**
  - test first and watch it fail;
  - every test must fail if its behaviour is removed;
  - "it renders" alone is not a test.
- **Before every commit:** `pnpm lint && pnpm typecheck && pnpm test && pnpm test:coverage`, plus the e2e subset named in the task.
  - Stage explicit paths only.
  - Never commit failing tests.
  - Never push: the controller pushes and checks the real CI run.
- **Single owners of shared files:**
  - `app/routes.tsx` and `app/TopBar.tsx` belong to **M2** only;
  - `kit/index.ts`, `kit/kit.css` and `dev/KitPage.tsx` belong to **M1** only.
  - Existing e2e specs are edited by **M2** (to keep them green after the nav change) and **M10** only.
- **Review cadence (R66):** there is no per-task reviewer loop. There is one review per phase:
  - Phase A: M1–M2;
  - Phase B: M3–M5;
  - Phase C: M6–M9;
  - Phase D: M10–M12.
  
  The final reviewer pass for safety and data loss runs in M12.

- **M-D2. The Forge returns to the navigation (overrides spec D27 and the D60 placeholders).**
  - The TopBar holds the wordmark, then campaign-scoped keys **Forge · Codex · Settings** (the active key is pressed-in), then the existing theme icon key.
  - With no current campaign, it shows only the wordmark and the theme key.
  - Below 768 px, the existing Menu collapse holds the same keys.
  - `MODES` becomes Forge and Codex. The Settings key is a separate entry.
  - `ModeShell` and its `/prep` and `/table` placeholders are deleted (redirects instead), so no dead CTA remains.
  - `docs/ui-page-patterns.md` changes `/forge`'s target from "List of generators" to "3 Form (page)" (M11).
  
  · R66 makes the Forge the product's main rolling surface, and Table and Prep, which D27 relied on, are deferred. · The Forge may later move inside Table Mode; it is one nav entry to drop.

- **M-D3. The Forge page is Pattern 3, Form (page).**
  - **The user's one job:** produce one card and keep it as a Codex entry.
  - **Layout:** a ~640 px column with labels above the controls:
    - **Generator** (a native select of all 15 `GENERATORS`, default `fantasy.npc`);
    - **Names from** (a native select of the campaign's `cultureIds`, by `CULTURES` name, default the first);
    - a safety line, "Rolling under your session-zero choices: {n} lines, {m} veils.", with a link **Change them in Settings**;
    - **Roll** (solid key);
    - the card (M6 `ForgeCard`).
  - **Sticky footer:** **Roll again** (outline; rerolls unlocked fields) and **Save to Codex** (solid, primary).
  - **Submit is never disabled.** With no card, **Save to Codex** shows the inline message "Roll a card first, then save it." and focuses **Roll**.
  - **Dirty** means a card is on screen, at least one field is locked, and it hasn't been saved since the last change. Navigating away when dirty opens the `useDirtyBlocker` Dialog: "Leave without saving this card?" with **Leave page** and **Keep editing** (focused).
  - **After a save,** a polite status reads "Saved '{title}' to the Codex." with a link **Open it**. The card stays on screen, and its saved state clears dirty.

  · The nearest catalog pattern: the page creates one record. A generator gallery (List) adds a page for no R66 need. · If the owner wants a generator list later, it becomes a List that links to this Form.

- **M-D4. Create and edit entry are one Form (page) component, not slide-overs.**
  - **Edit** has more than 3 fields (per-kind fields from D59, aliases, body), so it is ≥10 s. `surfaces` puts that on a route.
  - **Create** (`/c/:cid/codex/new`) is the **full** kind-dependent form, the same component as edit:
    - **Kind**, then a **Type** select that appears for place, item, note and scene (branching);
    - **Title**, **Summary**, that kind's fields, and **Notes** (body).
    
    The branching and the field count make it a ≥10 s task, so a route is correct under `surfaces`.
  - **Create from a wiki link** (`Create "X"` on a Detail page) navigates to `/c/:cid/codex/new?title=X&from=<eid>`. After saving, it returns to the originating entry (`from`), where the link now resolves through D56 incoming re-resolution. Without `from`, it goes to the new entry.
  - **Cancel** returns to `from`, or else to the Codex list.
  - Dirty navigation uses `useDirtyBlocker`: "Leave without saving this entry?" with **Leave page** and **Keep editing**.
  
  · It builds no `SlideOver` and no D66 swapped footer, avoids stacked modals entirely, and keeps state in the URL. Cheaper, and it passes `surfaces` and `forms`. · A DM creating a bare title loses the page context for a moment. The return-to-`from` behaviour limits that.

- **M-D5. Kit scope.** Build only:
  - `Dialog` (+ `useFocusTrap`): destructive confirms, the restore replace and dirty navigation;
  - `EmptyState`;
  - `Pagination`;
  - the icons `plus`, `search` and `restore`.
  
  Do **not** build `SlideOver`, `Popover`, `Banner`, `Kbd`, `Segmented`, `Switch`, `Combobox` or `MenuButton` (backlog):
  - The safety picker uses **native radio inputs** inside a `<fieldset>` per topic, styled as R31 keys. Native radio groups give arrow keys and one tab stop for free, with no custom ARIA.
  - The keyboard setting uses a native checkbox.
  
  · Native controls are the cheapest accessible option, and every S2 overlay without an R66 job is cut. · S3 and S4 build the rest when Table and Prep need them.

- **M-D6. Generator → Codex kind, and field labels (`content/fields.ts`, total tables).**

  | Generator | kind / subtype | Generator | kind / subtype |
  | --- | --- | --- | --- |
  | `fantasy.npc` | npc | `fantasy.rumor` | note / rumor |
  | `fantasy.place` | place / location | `fantasy.complication` | note / complication |
  | `fantasy.settlement` | place / settlement | `fantasy.encounter` | note / encounter |
  | `fantasy.tavern` | place / tavern | `fantasy.seed` | note / seed |
  | `fantasy.shop` | place / shop | `fantasy.secret` | note / detail |
  | `fantasy.clue` | clue | `fantasy.prep.pressure` | note / detail |
  | `fantasy.treasure` | item / treasure | `fantasy.prep.spotlight` | note / detail |
  | `fantasy.trinket` | item / trinket | | |

  `FIELD_LABELS` covers **every** generator field key, in sentence case. Use D59's labels where they exist; the rest are:

  > `item` Item · `text` Text · `truth` True? · `source` Heard from · `trouble` Trouble · `twist` Twist · `question` Question · `a` First situation · `b` Second situation · `enemy` Enemy · `friend` Friend · `complication` Complication · `thing` Thing · `place` Place · `pressure` Pressure · `hook` Hook · `rumor` Rumor · `name` Name · `delivery` How it's found · `trace` What it shows · `where` Where · `worth` Worth · `detail` Detail · `turn` Turn

  `FIELDS_BY_KIND(kind, subtype)` is D59's table. For **front** in this release, it is `portent` and `doom`: plain text fields, with no clock UI (M-D10).

  A test iterates `GENERATORS` × each generator's field keys (read from `lib.generator(id).fields`). It asserts every key has a label and every generator has a kind, so a new generator or field fails CI.

  Saving uses `entityFromCard(card, kind, { campaignId, subtype, origin: 'manual', canon: 'kept' })`, then `createEntity`.

  · `origin` is **not** widened to `'forge'`: Task 8's zod schema enumerates the origins, and saving is the DM's explicit choice ("manual"). · A future "where did this come from" filter can't tell Forge saves from hand-made entries. The stored `card` still marks them.

- **M-D7. Names on the Forge (R63 lands here).**
  - The Forge passes `avoidNames` from `avoidNamesFor(d, cid)` (newest first), **reversed to chronological** at the call site (`toEngineAvoid(list) = [...list].reverse()`), because the engine keeps `avoid.slice(-8)`.
  - The M6 test seeds 12 used names and asserts that the 8 **most recent** reach the engine (spy on `rollGenerator`'s `extras.avoidNames`, and check that its last 8 are the newest 8).
  - Saving an NPC records nothing in `usedNames`; NPC titles already feed `avoidNamesFor`.
  
  · It closes R63 at its first caller. · None.

- **M-D8. Live safety on the Forge.**
  - The page reads the campaign through `useCampaign(cid)` (a live query). Roll, reroll and recheck always read `campaign.safety` at call time, never from a captured closure.
  - When the live `safety` value changes (another tab, or Settings in the same tab before navigation), an effect calls `recheckCard(card, safety)` on the unsaved card on screen. This is §9: `applySafety` on unused cards only, with no reshuffle.
  - A locked field whose source now carries a line becomes blocked (R22). Saved Codex entries are never rewritten (D12).
  
  · It is the only way a card on screen could ignore a new line. · None.

- **M-D9. Multiple campaigns without `/campaigns`.**
  - Home's header has a secondary **New campaign** link to `/campaigns/new`.
  - When more than one campaign exists, Home's supporting list "Your campaigns" shows the others: name links to `/c/:cid`, plus "updated {d MMM}". That is the Dashboard's supporting list.
  - Settings → Danger zone deletes the current campaign. `currentCampaignId` then moves to the newest remaining campaign (existing repo behaviour).
  
  · It keeps create-and-switch without a List page. · If a DM runs many campaigns, `/campaigns` returns from the backlog.

- **M-D10. Codex scope.**
  - **List:** columns Title (pencil link), Kind (label plus muted subtype), Summary (one line), and Updated ("{d MMM}"). The default sort is `updatedAt`, newest first.
    - There is **no** Filters control, no Last seen, no Status, no shortlist and no export in the toolbar. The List pattern requires search, not filters, and a filter must match a visible column.
    - Search ("Search the Codex", visible label) uses `search(buildIndex(entities), q)` from Task 7. With `q`, rows are the ranked results (at most 20) and the frame shows "Showing the best matches for "{q}"."
    - 50 per page. Pagination always renders. `?q=&page=` live in the URL (D69, debounced 150 ms, `replace`).
  - **Detail:** no tabs, because Connections and History are cut. Its sections:
    - Summary;
    - Details: the `FIELDS_BY_KIND` keys first, then **every other non-empty `entity.fields` key**, as label/value rows through `fieldLabel()`; empty ones omitted. Forge saves carry keys D59 doesn't list (seed `enemy`, treasure `item`, rumor `text`, and so on), so Details must not hide them;
    - "Also called …";
    - Notes (`WikiText`);
    - veils as the margin note "veil: {topic}, fade to black";
    - the D64 card notice ("Part of this came from a table that touches one of your lines ({topics}).", plus the stale line).
    
    Its header has the breadcrumb "Codex › {Title}", the kind and subtype, Kept/Provisional as plain text (no pill), and the actions **Edit** (link) and **Delete entry** (outline key → Dialog).
  - **Fronts** have no clock UI in this release; `clock` stays at its default.
  - **States** (clue, truth, front, scene, thread) are a native select on the form, shown as text on Detail.
  
  · R66 keeps search and edit, and drops the rest. · Fronts lose their interactive clock until Table Mode.

- **M-D11. Keyboard.**
  - The one single-key shortcut is `/`, which focuses the Codex search (the List pattern's Must). It ships **together with** the Settings → Keyboard checkbox "Single-key shortcuts" (help text: "Turn off if you use speech input or keep pressing keys by accident."; device setting `singleKeyShortcuts`, D50 and D55), for WCAG 2.1.4.
  - `useShortcut` ignores events from `input`, `textarea`, `select` and `[contenteditable]`, and while an `[aria-modal="true"]` is open.
  - There is no `Mod+K` and no Pull anything.
  
  · Smallest WCAG-compliant shortcut set. · None.

- **M-D12. Storage failures without the S5 fallback.**
  - `main.tsx` opens the db before rendering the router. If `db.open()` rejects, the app renders a single in-pattern page with the h1 "Prep Desk can't save in this browser" and the sentence "This browser is blocking storage, so nothing you make could be kept. Try another browser, or leave private browsing." It shows no fake-indexeddb fallback and no Banner.
  - A `versionchange` from another tab closes the connection (existing `attachLifecycle`). The handler sets an app-level flag that renders the same page with "Prep Desk was updated in another tab. Reload to keep going." and **Reload**. Schema v1 never triggers it in this release.
  - Write failures inside forms show the D67 form-level error and keep the values.
  
  · No silent data loss, at the cost of no in-memory mode. · Private-mode Firefox users can't use the app until S5.

### Task M1: Kit: Dialog, EmptyState, Pagination, icons and the dirty-navigation hook

**Files:**

- Create: `apps/web/src/kit/{Dialog.tsx,useFocusTrap.ts,EmptyState.tsx,Pagination.tsx}`, `apps/web/src/app/useDirtyBlocker.tsx`
- Modify: `apps/web/src/kit/{index.ts,kit.css,Icon.tsx}`, `apps/web/src/styles/tokens.css` (add `--z-dialog: 60` and `--scrim` in light and dark), `apps/web/src/dev/KitPage.tsx` (a demo of each)
- Test: `apps/web/src/kit/__tests__/overlays.test.tsx`, `apps/web/src/app/__tests__/useDirtyBlocker.test.tsx`

**Interfaces:**

- `Dialog({ open, title, children, confirmLabel, onConfirm, onCancel, cancelLabel = 'Cancel', tone?: 'destructive' })`:
  - `role="dialog"` with `aria-modal="true"`, labelled by its title (an h2);
  - it renders in a portal at `--z-dialog` over a scrim, and locks page scroll;
  - **Cancel has the default focus**, and Tab and Shift+Tab are trapped;
  - Escape and Cancel call `onCancel` and return focus to the opener;
  - when destructive, the confirm is a solid key in stamp red;
  - no motion under reduced motion.
- `EmptyState({ title, sentence, primary: ReactNode, secondary?: ReactNode })`: an h2, a sentence and the CTA keys. No illustration.
- `Pagination({ page, pageSize, total, onPage, label })`:
  - a `nav` labelled `label`, with **Previous** and **Next** keys that keep their visible text;
  - mono text "Page 2 of 7 · 312 entries";
  - at an end, the key is disabled but keeps its readable label;
  - `total 0` reads "Page 1 of 1 · 0 entries".
- Icons in the existing style (22 px box, 1.7 stroke, round caps): `plus`, `search` and `restore`.
- `useDirtyBlocker(dirty: boolean, copy: { title: string; leave: string }): ReactNode`:
  - react-router `useBlocker(dirty)` plus a `beforeunload` listener while dirty;
  - it returns the Dialog element (non-destructive tone), whose confirm is **Leave page** and whose cancel is **Keep editing**.

- [ ] **Step 1: Write the failing tests.**
  - **Dialog:**
    - Cancel is focused on open;
    - Tab and Shift+Tab cycle inside;
    - Escape calls `onCancel` and not `onConfirm`, and focus returns to the opener;
    - the destructive confirm carries the destructive class;
    - the body gets the scroll lock and loses it on close.
