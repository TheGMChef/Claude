# MVP Slice S2 (Persistence and Codex) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give Prep Desk a memory. A DM can create a campaign with session-zero safety, land on a real Home, and keep a Codex of NPCs, places, fronts, truths, clues, scenes, threads, items and notes in IndexedDB. Entries are wiki-linked, findable with Pull anything, exportable as a JSON backup and an Obsidian-style Markdown zip, and restorable from the backup. It all works offline, and nothing leaves the device.

**Architecture:** One Dexie database (`prepdesk`, schema version 1, all eleven stores frozen at the S2 merge so S3 and S4 add no migration) lives in `apps/web/src/data`. That folder is plain TypeScript: it imports `@prepdesk/engine` and Dexie, and never React (except `data/hooks.ts`). Repository functions take an injected `RepoDeps` (`db`, `now`, `newId`), so tests are deterministic on `fake-indexeddb`. Every write is one Dexie transaction (write-through, D44). The UI reads through `useLiveQuery`. Engine calls that take safety go through `content/safety.ts`, which always injects the campaign's **current** safety. An ESLint rule bans calling the raw engine functions anywhere else (Security B). Seven routes are built on named page patterns: Dashboard, List, Form, Settings, List, Detail, plus redirects. Slide-overs, popovers and dialogs come from new kit components.

**Tech Stack:** TypeScript (strict), React 18, react-router 7 (data router), Dexie 4 + dexie-react-hooks, zod 4 (the engine's instance, jitless), fflate 0.8 (`zipSync` only), Vitest + Testing Library + `fake-indexeddb/auto`, Playwright + @axe-core/playwright.

**Spec:** `docs/superpowers/specs/2026-11-08-mvp-design.md`. This plan covers:

- §5 (S2) in full;
- §7.1 (campaign create, settings and Home, built in S2);
- the S2 parts of §3 (layers, state, routes, TopBar, kit), §8.3 (the S2 empty states), §9 (safety), §10 (`/`, `Mod+K`, Escape and the single-key switch), §11 and §12;
- decisions D4–D6, D12, D22–D28, D36, D39, D40, D44, D45, D47 and D50.

The foundations spec still binds. Where a delivered engine signature differs from spec §2.2, the delivered one wins (for example, `parseCard(lib, json)` takes `lib` and returns `stale`).

## Global Constraints

**From CLAUDE.md and spec §2.1:**

- **Engine boundary:** `packages/engine` imports nothing from the repo and no DOM types. The web app imports compiled JSON packs only. **S2 changes nothing in `packages/`.** If an engine change looks necessary, stop and report it to the controller.
- **Safety beats everything.** Lines are never selected, never relaxed, and they override locks. The campaign's `{ lines, veils }` reaches every engine call through `contextFor()` (§9). The UI never filters text by itself. The DM's own text is never filtered or flagged.
- **Safety vocabulary** (exact, from `SAFETY_VOCABULARY`): `violence, gore, death, torture, sexual-content, abuse, child-harm, self-harm, suicide, addiction, slavery, body-horror, insects, spiders, rats, drowning, fire, claustrophobia, religion, hate-bigotry, animal-harm, pregnancy, mental-illness, police, war`. - **Accessibility:**
  - every interactive target is at least 44×44 px, with the 2 px pencil focus ring;
  - text contrast is at least 4.5:1 in light and dark;
  - `prefers-reduced-motion` is respected;
  - there is no horizontal page scroll at 1194, 834, 1440, 390, 375 or 1280 wide;
  - axe reports zero serious or critical violations in light and dark.
- **Styling:** tokens in `apps/web/src/styles/tokens.css` only, with no raw hex in component CSS. Ink goes on borders, never on text. Keys are R31 raised keys. No pills.
- **No third-party requests.** Fonts are self-hosted. The strict CSP in `public/_headers` stays untouched: no `unsafe-*`, no `blob:` in `worker-src`, and no `eval` or `new Function` at runtime. **Never** use `dangerouslySetInnerHTML`, `innerHTML` or any HTML string: wiki text renders as React text nodes.

## Decisions this plan makes where the spec is silent (binding for all tasks)

Each reads: decision · why · cost if wrong. They continue the spec's numbering.

- **D51. Data layer location.** `apps/web/src/data` stays in the web app (spec §3.1), not a new package. The boundary is enforced by an ESLint override: `src/data/**` may not import `react`, `react-router`, `../kit`, `../features` or `../app`, except `data/hooks.ts`, which may import `react` and `dexie-react-hooks`. A test in `data/__tests__/boundary.test.ts` scans imports the same way `router-deps.test.ts` does. · Dexie needs the DOM's IndexedDB anyway, so a package would gain nothing but build plumbing. · If a second app (CLI, sync worker) needs the repo, move the folder into `packages/data`: imports change, code does not.
- **D52. Database name and class.** The database is named `prepdesk` (§5.1), and the class is `PrepDeskDB` (§8.1 names the class). The factory is `createDb(name = 'prepdesk', opts?: { indexedDB?: IDBFactory; IDBKeyRange?: typeof IDBKeyRange })`, and the `opts` slot is what S5's in-memory fallback (D26) fills. · It resolves the §5.1 / §8.1 naming mismatch. · A rename after release needs a copy migration.
- **D53. Schema v1 is final at the S2 merge and holds all eleven stores** (S3 and S4 write into them with no `version(2)`). Three changes to §5.1 are made **now**, while they are free:
  - (a) `Draft` and `PrepAnswer` gain `campaignId`, and `pocket`, `drafts` and `prepAnswers` gain a `campaignId` index, so deleting or replacing a campaign is a plain `where('campaignId')` on every store with no session-id cascade;
  - (b) `entities` gains `*wikiTargets` (D56);
  - (c) `sessions` gains `[campaignId+status]` (only one live session per campaign; Home's "next session").
  
  The final v1 store strings are in Task 2. · A v2 migration for something known today is waste. · If S3 or S4 find another missing index, they add `version(2)` with a migration test (§5.8). The harness exists from Task 2.
- **D54. Repository shape.**
  - Every repo function is `fn(deps: RepoDeps, …args)`, where `RepoDeps = { db: PrepDeskDB; now: () => number; newId: (prefix: IdPrefix) => string }`.
  - `liveDeps(db)` wires in `Date.now` and `newId`.
  - Tests use `testDeps()`: a fresh fake-indexeddb database with a unique name, a fixed clock that advances 1 ms per call, and counter ids (`ent_0000000000000001`, …).
  - Repo functions throw on invalid input (a typed `RepoError` with a `code`), and write in exactly one `db.transaction('rw', …)`.
  
  · Deterministic snapshots (Markdown, export) and easy assertions. · Slightly more parameters at call sites.
- **D55. Device settings vs campaign settings.**
  - Campaign data (name, `safety`, `cultureIds`, `lastExportedAt`) lives on the `campaigns` row.
  - Device settings live in `settings` as `{ key, value }`. The keys are `currentCampaignId`, `singleKeyShortcuts` (default true), `persistRequestedAt`, and later `tableHintSeen` and `e2eSeed`.
  - The theme stays in `localStorage` (it must apply before paint, through the hashed inline script).
  - Settings are **not** exported in backups.
  
  · Safety travels with the campaign and its backup; device choices do not. · A DM restoring on a new device sets shortcuts again.
- **D56. Wiki links.**
  - **Syntax:** `[[Target]]` or `[[Target|shown text]]`. There is no escape syntax. The target is trimmed, and an empty target is plain text.
  - **Titles and aliases** may not contain `[[`, `]]` or `|`. Form error: "Titles can't contain [[, ]] or |."
  - **Folding** is `fold()` from `data/text.ts`: NFKD, combining marks removed, lowercase, whitespace collapsed.
  - **Resolution** (within the campaign, the entity itself excluded): the first entity whose folded title equals the folded target, then the first whose folded alias equals it. "First" means the oldest `createdAt`, then the smallest id. Duplicate titles are **allowed**, and the forms warn "There's already an entry called 'X'. Links go to the oldest one." (warning, not error).
  - **Derivation** (`deriveWikiLinks`, on every create or update): parse `body` and every value in `fields` and `summary`. Set `entity.wikiTargets` to the folded targets. Replace this entity's `origin: 'wiki'` links with one `mentions` link per distinct resolved target.
  - **Incoming re-resolution:** on **create**, **rename** and **alias change** of entity X, every entity whose `wikiTargets` contains X's folded title or one of its folded aliases is re-derived in the **same transaction**. So clicking **Create "Odrin"** on A's unresolved link immediately gives Odrin a "Mentioned by A".
  - **Rename (D47):** in every entity with an `origin: 'wiki'` `mentions` link that resolves to X (and only those), in the same text the parser reads (`body`, every value in `fields`, and `summary`), rewrite `[[Old]]` and `[[Old|shown]]`, matching Old by folded comparison, to `[[New]]` and `[[New|shown]]`. Then add Old to X's aliases (if not already there by folded comparison) and re-derive.
  - **Delete:** links to the deleted entity are removed, and text is never rewritten. The old `[[X]]` renders as **Create "X"**.
  
  · Links never silently break, and creating from a link closes the loop. · One extra multi-entry index, and rename transactions touch more rows.
- **D57. Connections.**
  - Wiki-derived `mentions` links appear under Mentions or Mentioned by with the note "from the text". They have **no** remove key, because they would come back on the next save. The DM edits the text instead.
  - Explicit links (`origin: 'explicit'`) have a remove key. Removing one asks for confirmation ("Remove the link between 'A' and 'B'?" with **Remove link**), because `.ux-profile.md` rule 5 requires a confirm for every destructive action.
  - **Add connection** offers the five outgoing relations (Mentions, Points to, At, Part of, Knows) in a native select, plus the entry picker. An exact duplicate (same from, to and rel) is refused with "Those are already linked that way."
  - The reverse labels are fixed: points-to → "Pointed to by", at → "Here", part-of → "Has part" (the spec lists "Part of" both ways; the reverse needs its own label), knows → "Knows" (symmetric: shown once, both directions), mentions → "Mentioned by".
  
  · It keeps the text as the source of truth for wiki links. · DMs may look for a remove key on wiki links; the note explains.
- **D58. Search** (`data/search.ts`, §5.6):
  - **Tokens:** `tokenize(text) = fold(text).split(/[^\p{L}\p{N}]+/u)`, with empty tokens dropped. `entity.tokens` = the distinct tokens of title, aliases, summary, every field value and the kind label. The body is not indexed (§5.6).
  - **Ranking:** with `qf = fold(q).trim()`:
    - exact title 100;
    - title starts with `qf`: 60;
    - an alias equals or starts with `qf`: 50.
    
    Otherwise every query token must prefix-match some token (AND), and the score is the sum over query tokens of the best of: title token prefix 40, alias token prefix 30, any other token prefix 10. Add 5 if `updatedAt` is within 7 days of `now`. Ties go to newer `updatedAt`, then title A–Z. At most 20 results.
  - **Commands:** `matchCommands(q)` matches a verb or noun prefix against the fourteen §5.6 commands. It is built and tested in S2, but **not rendered** until S3 (D60).
  - **In-memory index:** `buildIndex(entities)` is a pure structure, rebuilt by `useSearchIndex(cid)` with `useMemo` over the live entity list.
  - **Budget:** ≤ 20 ms per query, median of 30 queries, over 5,000 entities in jsdom (§5.6). This is a hard test.
  
  · Spec rules made exact. · If the jsdom timing flakes in CI, it becomes a reported bench like the engine's (controller ruling).

Those are the already-audited `ModeShell` stubs, replaced by S4 and S3. · `ux-audit` gate 10 scores dead or placeholder CTAs as unfinished. · Two TopBar keys still reach placeholders until S3 and S4; recorded in `docs/ui-page-patterns.md`.

- **D62. Restore reaches a DM with no campaign.**
  - **Restore from backup** appears in Settings → Data (§5.9), and also as the header secondary action on `/campaigns` and as the secondary action on Home's first-run empty state ("Restore from backup").

- **D63. Restore validation** (`data/export/restore.ts`). The checks run in this order, and any failure restores nothing:
  1. The file is at most 50 MB. Otherwise: "That file is too big to be a Prep Desk backup. Choose a .json file exported from Prep Desk."
  2. JSON parse.
  3. `format === 'prepdesk-export'`.
  4. `formatVersion` is an integer ≥ 1. If it is greater than the current one: "This backup was made by a newer Prep Desk. Update the app, then try again."
  5. Upgrade in code to the current format (`upgrade.ts`; v1 is the identity).
  6. zod `strictObject` schemas for every record, with:
     - string caps (titles 200, text fields 20,000, bodies 200,000);
     - array caps (aliases 50, entities 50,000, ledger 200,000);
     - safety topics `z.enum(SAFETY_VOCABULARY)`;
     - ids matching their prefix pattern;
     - any `__proto__` or `constructor` key rejected.
  7. **Every** record's `campaignId` equals `campaign.id`, every `sessionId` is a session in the file, and every link's `fromId` and `toId` is an entity in the file. A dangling `ledger.entityId` stays allowed (D8: the Ledger outlives let-go entities).
  8. **Cross-campaign collision:** no record id (or `[sessionId+step]` key) already exists under a **different** campaign on this device.
  9. Every `card` string passes `parseCard(lib, card)`. A card that fails is **removed**: `card` becomes `undefined`. Records that cannot live without a card are dropped: a shortlist item with no `entityId`, and a pocket item outside `names` with no card. The success status then adds "{n} saved cards couldn't be read and were left out. Your text is kept."
  10. `tokens` and `wikiTargets` are **recomputed**, never trusted.
  
  Failures in steps 2, 3 and 6–8 all show the §5.9 message: "That file isn't a Prep Desk backup. Choose a .json file exported from Prep Desk." Steps 1 and 4 have their own messages. If the campaign id already exists, the replace Dialog from §5.9 asks first. Replace runs as one `rw` transaction over all eleven stores: delete by `campaignId`, then `bulkAdd`.
  
  · A hostile or hand-edited file can't overwrite another campaign or plant unvalidated cards (Security B). · An unreadable card loses only provenance (D4: fields are the record).
- **D64. Lined-table notice (D12).**
  - `linedTopics(lib, cardJson, safety): string[] | 'unreadable'` parses with `parseCard`, then looks up every field's `sources` (and `hidden.sources`) as `tableId#index` entries in `lib.table(tableId)`, and returns the sorted intersection of their `safety` tags with **the campaign's current** `safety.lines`.
  - It never reads `card.context.safety`, never calls `applySafety`, and never throws (an unknown generator or table counts as no hit).
  - Detail shows the §5.4 sentence "Part of this came from a table that touches one of your lines (spiders)." when the result is non-empty.
  - A `stale` card also shows the muted line "Made with an older version of the tables." Ids may have shifted, so the check is best effort, and the text is the DM's record.
  
  · Both directions are tested (card `lines: []` with campaign `spiders` → notice; card `spiders` with campaign none → no notice). · A stale card can miss a hit; the DM's text was never auto-edited anyway.
- **D65. JSON and Markdown details.**
  - **Front-matter values** are written with `JSON.stringify` (valid YAML scalars and flow sequences), so no YAML dependency is added.
  - **Wiki links** in the vault become `[[stem]]` when the stem equals the target's title, else `[[stem|shown]]`. Unresolved links are left as written.
  - **Filenames:** `/\:*?"<>|` and control characters are removed, whitespace is collapsed and trimmed, the result is cut to 80 characters, and an empty name becomes "Untitled". Duplicates compare case-insensitively within a folder and get " (2)", " (3)".
  - **Session files** are `Sessions/Session 07.md` (two digits, three from 100).
  - **Ledger times** are `t` formatted `h:mm`.
  - **Downloads** go through `URL.createObjectURL(new Blob(...))` and an `<a download>` click, with the URL revoked afterwards. They are named `prepdesk-<slug>-<yyyy-mm-dd>.json` or `.zip` (local date; the slug is folded, lowercase ASCII words joined by `-`, at most 40 characters).
  - `lastExportedAt` is set after the download click.
  - `appVersion` comes from a Vite `define` (`__APP_VERSION__`, read from `apps/web/package.json`; still 0.1.0, and S5 bumps it to 0.2.0 per D46). Pack versions come from `lib.packs`.
